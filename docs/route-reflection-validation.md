# ラン後のルート・景色の振り返り：価値検証案

関連: #92、#94、#95、#102、試作 #105、後続の地図検討 #106。2026-11-08時点の検討案で、機能採用や公開の決定ではない。

## 確認できたことと未確認のこと

- ユーザーから、ラン後の記録を振り返りにくく、振り返りたい対象は「走ったルートや景色」、Garminの記録には「思い出として残したくなる表示がない」と回答があった。Garminのランを持っていることも確認済み。
- 2026-11-08、#105 の試作を専用Simulatorで表示し、架空のルートと同梱の秋の風景を重ねた画面をユーザーに見せた。「自分のランで作れるとしたら、思い出として残したいか」という質問への回答は「残したい」。1つの見本への仮定上の回答であり、実際の保存・再訪・共有や支払いの行動は確認していない。
- どの場面で残したくなるか、どんな表現が足りないか、繰り返し使う理由、支払い意思は未確認。1人の回答から一般的な需要を結論づけない。
- 合意済みの #105 はHealthKitのルートを地図なしで作品化する試作。同梱背景のみ、線色を選択でき、開始・終了付近の保護は初期オン。軌跡や背景から位置が推測される可能性は残る。
- 今あるGarminのランについて、HealthKitからルートは読み込めていない。実機のルート付きランは今すぐ用意できず、試作の実ルート検証は保留。HealthKit方式がこのユーザーの記録で使えるとは判断しない。

## 最小の検証案

1. 直近で振り返りたかったランについて、どの記録をどこで見て、どんな表示なら思い出として残したくなるかを聞く。正確な位置や画像の提出は求めない。
2. 既存画面で十分な点と足りない点を聞き、ルートの形、実際の景色、場所の文脈、共有のどれが必要かを分ける。景色を同梱背景で代替できると決めつけない。
3. #105 の架空サンプルへの肯定的な回答を出発点に、見返す場面・役立つ点・足りない点を確認する。実データの動作確認とは分ける。地図や本人の写真を初期版へ追加しない。
4. 条件: 具体的な場面と既存手段の不足が説明でき、試作がその不足を解消する見込みがあれば実ルートでの検証へ進む。景色や場所の文脈が不可欠なら #105 の表現を見直し、代替で十分なら追加開発を保留する。再利用・支払いは別途、実利用や具体的な条件で確かめる。

## MVPの仮置きと境界

- 対象はラン後に自分のルートを見返したい人、場面は一回のランの後を仮置きとする。まだ対象の代表性や頻度は不明。
- 試作の入力は読み取り許可されたHealthKitのランとルート、出力は地図なしの作品プレビューと明示操作による保存・任意共有。欠けた情報は作らない。
- 技術・保存・保護・権限の候補と未確認事項は [試作記録](route-art-spike.md) と [後続作業案](route-art-delivery-plan.md) を参照する。既存のタイマー・保存履歴は変更しない。
- 実データの検証、実装範囲、権利・プライバシーの確認と公開判断を経るまで、配布や審査提出は決めない。地図、本人の写真、Garmin連携は別途採否と条件を検討する将来候補。
