# iOS 回帰チェックリスト

Issue #14 の公開前チェックです。自動テストで検証できない iOS 固有の挙動を、iOS 17 以上の iPhone Simulator と実機で確認します。実機では通知を許可した状態と拒否した状態をそれぞれ確認します。

Issue #16 のTestFlight・実走QAでは、このチェックリストに加えて [iOSベータQA記録](ios-beta-qa-record.md) の対象端末、通知結果、電池・発熱、残存リスクを記録します。MVPは時間ベースのローカル通知のみで、GPS距離計測は対象外です。

## 実行前

- [ ] `make lint typecheck test build` が成功する
- [ ] Simulator と実機で最新ビルドを起動できる
- [ ] 実機で通知許可・拒否を切り替えられる

## 設定とセッション

- [ ] 「補給を通知する」をオンにすると、10・20・30・40分ごとの補給ペースと、通知を止める予定を選べる
- [ ] 「通知を調整」から、10〜240分の通知間隔、通知を止める予定、通知メッセージを変更でき、プレビューに反映される
- [ ] 開始画面で10分を選び通知調整を初めて開いたとき、選択欄・説明文・メニューの選択状態がすべて10分になる（#79）
- [ ] 通知調整で間隔・メッセージ・画面外通知を変更すると説明・プレビューも即時更新され、キャンセルでは本設定を変更せず、完了時だけ反映される。閉じて再表示しても一致する（#79）
- [ ] 通知メッセージは空欄でも開始でき、既定の「補給の時間です」で通知される。31文字以上は保存されない
- [ ] 「補給を通知する」をオフにすると、通知なしで開始でき、タイマーだけを利用できる
- [ ] 通知を許可して開始し、補給通知が予定どおり届く
- [ ] 一時停止中は経過時間と次回予定が進まず、再開後は停止時間を除いて進む
- [ ] 終了後は設定画面へ戻り、終了済みセッションを再開できない

## iOS 固有の状態遷移

- [ ] 実行中にアプリをバックグラウンドへ移し、予定時刻を過ぎて復帰しても、経過済み予定が次回予定として再表示されない
- [ ] 画面ロック中・集中モード中・消音中の通知表示と音／振動が iOS 設定に従う
- [ ] 通知を拒否した場合、タイマーと画面上の次回予定は継続し、通知設定の案内が表示される
- [ ] 通知予約に失敗した場合、タイマーは継続し、予約失敗の案内が表示される
- [ ] アプリを強制終了して再起動した場合、実行中セッションが復元されないことを確認する。終了前に予約した通知が残らないことも確認する

## 保存とアクセシビリティ

- [ ] 補給ペース、通知を止める予定、通知メッセージ、画面外通知の設定を変更して再起動しても保存される
- [ ] 設定を初期化すると初期値に戻る
- [ ] VoiceOver で補給ペース、通知を止める予定、通知メッセージ、開始、一時停止／再開、終了、次回予定を操作できる
- [ ] Dynamic Type を最大にしても主要な操作が可能

## Live Activity（#69）

- [ ] 開始→背面→ロックで経過時間・実行状態・更新時点の補給予定を確認できる
- [ ] 送信した予定時刻を過ぎると、古い予定の代わりにアプリ確認案内が表示され、前面復帰で最新の予定へ更新される
- [ ] 摂った／スキップで記録済み予定が除外され、後続予定の時刻を変えない
- [ ] 停止中の経過・残り時間が固定され、再開後は停止時間を除いて進む
- [ ] 通知なし／予定なしでも経過・状態・予定なしを表示する
- [ ] Live Activity無効・開始失敗でもアプリ内タイマーと通知処理を継続する
- [ ] 終了で表示が消え、完全終了後の残留表示は再起動時に削除される
- [ ] 実機の長時間制限・通知整合・アクセシビリティ・実走結果を [Live Activity QA](live-activity-qa.md) と #75 / #76 に記録する
