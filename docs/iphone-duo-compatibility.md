# iPhone Duo・可変画面の互換性確認（Issue #150）

2026-11-07 時点の調査。通常の小画面Simulatorで一部を目視確認したが、iOS 27 SDKでのビルドやDuoでの確認はまだ実施していない。この記録は互換性・審査・公開の完了を意味しない。既存の実機確認は #75、#89、ルートアート試作は #105 の結果をそれぞれ参照する。

## 現在の環境と設定

- 選択中のXcodeは 26.2（17C52）、iOS／Simulator SDKは 26.2。インストール済みSimulatorランタイムはiOS 17.4、18.3.1、26.2。iOS 27 SDKとDuo Simulatorはこの環境では確認できず、Duoの開閉・可変サイズ・iOS 27.1以降の縦配置バーは未検証。
- `main` のXcodeプロジェクト設定では、アプリの最小対応OSはiOS 17.0、対象はiPhone、対応するiPhoneの向きは縦。最小対応OSとビルドに使うSDKは別の設定であり、SDK更新を理由に最小対応OSを変更しない。作業ツリーには既存の未コミットのプロジェクト変更があるため、上記の設定確認は `git show HEAD:RaceFuelTimer.xcodeproj/project.pbxproj` の結果を記録した。実際のビルド結果は作業ツリーの設定にも影響され得る。
- [Appleの提出要件](https://developer.apple.com/app-store/submitting/)によると、2027年4月以降にApp Store ConnectへアップロードするiOSアプリはiOS 27 SDK以降でのビルドが必要。これは既存公開版の即時配信停止を意味せず、適用条件は提出前に再確認する。
- [Appleのスクリーンショット仕様](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications)では、2027年4月以降、iOS 27.1 SDK以降で作られたアプリにDuo用スクリーンショットが必要とされる。SDKの提出要件とは条件が異なる。掲載されている縦向きサイズは外側1398×2034、内側2007×2853ピクセル。実素材の取得・提出は未実施で、対象SDKと最新仕様を提出前に再確認する。

## ソースからの点検

`RaceFuelTimer/Features` と `RaceFuelTimerLiveActivity` のSwiftコードを、`UIScreen`、画面の `bounds`、画面サイズ・向きによる分岐、`GeometryReader`、固定 `frame` といった語で検索し、開始画面・タイマー・設定・履歴の構造を目視した。画面幅・高さを固定する `frame`、`UIScreen` の参照、端末種別・向きによる分岐は、この検索範囲では見つからなかった。開始画面は `ScrollView` と `safeAreaInset`、設定は `Form`、履歴は `List`、実行中は `ScrollView` を使用している。

この検索はレイアウトの正常性を証明しない。以下は**不具合と断定せず、優先して実画面で確かめる箇所**。

| 場所 | 確認すること |
| --- | --- |
| 開始画面の横並びの間隔・終了予定ボタン | 狭い画面と大きな文字で選択肢が欠けず、選択中の値と開始ボタンに到達できるか |
| 実行中の大きな経過時間表示と横並びの「摂った／スキップ」 | 狭い幅や大きな文字でも読め、操作できるか。再レイアウト後も時間・次の予定・記録を維持するか |
| 設定シートのピッカー、テキスト入力とキーボード | 狭い／広い表示と開閉中に未保存の入力を維持し、完了・キャンセルの両方を操作できるか |
| 履歴・今週の振り返り・終了サマリー | 行の値や説明が見切れず、詳細や削除確認へ到達できるか。既存の #89 の実機QAとは分ける |
| 情報メニューと安全・プライバシーのシート | ナビゲーション、ツールバー、閉じる操作、安全領域が使えるか |

## 残りの検証手順

1. iOS 27 SDKとDuo Simulatorが利用できる環境で、使用Xcode・SDK・OS・端末、ビルド設定とコミットを記録する。既存の未コミット変更は対象から外すか、影響を区別して記録する。
2. 外側→内側→外側へ連続切替し、開始画面、設定中、実行中、一時停止中、終了確認、サマリー、履歴を確認する。入力値・時間・次の予定・セッション状態を比較し、通知やLive Activityが再作成されないことを確認する。
3. リサイズ可能なSimulatorで狭い／広い領域も確認し、通常iPhoneと既存対応OSで回帰する。大きな文字、VoiceOver、ライト／ダーク、日本語で主要操作を確認する。試作を対象にする場合はプレビューと操作も別記する。
4. ロック中の通知到着とLive Activityは別途実機で確認する。取得不能な環境や未実施項目はそのまま記録し、Simulatorの結果を実機の成功として扱わない。
5. 対象SDKに応じ、Duo外側・内側の実画面素材と撮影手順を用意する。スクリーンショットの条件は提出直前に再確認し、TestFlight配布・審査提出・公開はこの調査だけで実行しない。

根拠: [Apple: iPhone Duoの準備](https://developer.apple.com/iphone-duo/prepare/)、[既存のiOS回帰チェックリスト](ios-regression-checklist.md)。

- 初回案内を閉じ、開始画面の通知間隔・終了予定の選択肢と開始ボタンが画面内に表示されることを確認。通知をオフにして開始し、タイマー表示、一時停止・再開、終了確認、終了サマリへの遷移を確認した。通知オフのため補給記録の操作は対象外。
- 終了後、架空のラン1件が今週の振り返り・履歴一覧・詳細に表示されることを確認した。通知設定シートとメッセージ入力時のキーボードも表示された。これらの確認中に、目視した範囲で文字や操作の欠けは見られなかった。

同じiPhone SE / iOS 17.4の専用Simulatorで、起動引数 `-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityXXXL` を使って文字を拡大した。修正前は通知間隔の4つのボタンが横並びのままで、「10分」などが1文字ずつ折り返された。

選択肢が横幅に収まらない場合は縦に並べる修正後、拡大時に「20分」「6時間」を選択し、折り返されない表示と選択後の説明文の更新を目視確認した。引数なしの標準文字サイズでは両方の選択肢が横並びで表示された。画像証跡は保存していない。VoiceOver・Duoでの検証は未実施。
