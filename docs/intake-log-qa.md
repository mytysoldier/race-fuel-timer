# 摂取ログ・終了サマリの確認（#68）

## 記録の仕様

- 「記録対象：開始からN分の予定」を確認して「摂った」「スキップ」を押す。
- 到来済みで未記録の最も古い予定を優先する。なければ次回予定を先に記録できる。
- 到来の推定と摂取記録は別。アプリへ復帰しても過去の未記録は消えない。
- 記録済みの未配信通知だけを取り消す。他の予定時刻は変えない。配信と同時の操作では、表示済み通知の取り消しを保証しない。
- 停止中は記録できない。再開後の経過時間と通知は停止時間を除く。
- サマリの予定数は終了までに到来した数。未到来は未記録に含めない。摂った・スキップは全記録数を表示し、未到来の先行記録を含む場合はその件数を注記する。
- 記録はセッション内メモリだけに保持する。設定画面への復帰・アプリ完全終了後に履歴として利用できない。

## Simulator回帰

通知間隔10分、通知終了予定30分を設定する。実際の通知音・振動・ロック画面での配信は実機で確認する。

1. 開始→10分の予定を先行して「摂った」→次回予定と記録対象が20分になる。
2. 20分の予定を「スキップ」→30分へ進む。同じ予定の連打では二重記録しない。
3. 一時停止→記録ボタンが無効→再開→再び記録できる。
4. 10分未満で終了→到来した予定0、摂った1、スキップ1、到来済み未記録0、先行記録2の注記を確認する。
5. 設定画面へ戻る→再開始→最初の10分から記録できる。前回ログを引き継がない。
6. 記録せず途中終了／通知なしプランで終了→0件サマリを安全に表示する。
7. 通知のみオフで予定がある場合も記録できる。通知拒否でもタイマーと記録を継続する。
8. 大きな文字・VoiceOverで対象予定、記録操作、サマリの項目と値を確認する。

時刻境界、過去予定、通知終了予定後、通知予約中の取消はSwift Testingでも検証する。Simulatorで長時間の実配信を待った結果とは区別する。
