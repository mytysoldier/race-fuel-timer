# ルートアートの事前調査（Issue #105）

調査日: 2026-10-31。これは文書調査の途中結果であり、実機での成立や公開を保証しない。

## 最新の合意

2026-10-31、地図を含めず、HealthKitの軌跡だけを作品化する方針に変更。色の選択・保存・任意共有は検討を継続する。以下の地図に関する調査は経緯として残し、本方式の実装条件にはしない。軌跡の形自体から位置が推測されるリスクは残る。

## HealthKit

- 読み取り対象はランの `HKWorkout` と `HKWorkoutRoute`。HealthKit capability と読み取り目的の説明が必要。書き込みは要求しない。
- 読み取り許可の拒否とデータが存在しない状態は確実に区別できない。空状態では「ルート付きのランが見つかりません。ヘルスケアのアクセス設定や記録を確認してください」と案内し、拒否と断定しない。期間限定の読み取りにも対応する。
- ワークアウトの保存後にルートが追加・更新され得る。対象ワークアウトのルートは anchored query で追加・削除を追跡し、各ルートの位置情報は route query の複数バッチを完了まで受け取る。最新のランにルートがなければ古いランも探し、更新時には再検索できるようにする。検索件数や負荷の上限は実測して決める。
- データベースがロック中に利用できない場合、取得失敗として再試行を案内する。位置をログに出力しない。

根拠: [ルートの読み取り](https://developer.apple.com/documentation/healthkit/reading-route-data)、[アクセス許可](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[HealthKitの設定](https://developer.apple.com/documentation/xcode/configuring-healthkit-access)。

## 地図と作品の未解決事項

- `MKMapSnapshotter` はアプリ独自の軌跡を含まないため、取得した画像に別途描く。地図タイルの取得には通信が必要で、失敗・不足時は保存や共有を成功扱いせず再試行を案内する。
- Appleの契約は地図の権利表示を隠すことを禁止し、地図データの保存や公開にも制限を設けている。**地図入り画像の永続保存・アプリ内再表示・共有が想定用途で許可されるかは未確認**。ロゴを残すだけで適法と判断しない。正式な条件を確認するまで、この方式を本実装の確定仕様にしない。
- 追加調査: 契約 Attachment 6 の 2.1 は権利表示の除去・隠蔽・変更を禁止、2.3 は原則として地図データの複製・改変・公開等を制限、2.5 は明示的な書面許可がない場合の保存を一時的・限定的な用途に制限する。[Maps Web Snapshotsの案内](https://developer.apple.com/news/?id=ftkfxb8m)には画像を取得・保存して埋め込む推奨があるが、これはWeb用サービスの案内であり、iOSの `MKMapSnapshotter` で生成した画像を作品として永続保存・共有できる根拠とは判断できない。
- 地図を含めない方針のため、この点についてAppleへの問い合わせは不要。
- 経路の分断・欠損は直線で無条件に結ばない。分断の判断基準、大きなルートの表示範囲、位置精度と処理負荷は実データで検証する。

根拠: [MKMapSnapshotter](https://developer.apple.com/documentation/mapkit/mkmapsnapshotter)、[Apple Developer Program License Agreement・Attachment 6](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)、[Maps HIG](https://developer.apple.com/design/human-interface-guidelines/maps/)。

## 画面とプライバシーの検討案

1. 作品作成を選択した時に用途を説明し、HealthKit読み取りを要求。
2. 直近のルート付きランを表示し、別のランも選択可能にする。取得中、見つからない、取得失敗、再試行の状態を用意する。
3. プレビューで色を選び、保存・共有前に自宅や開始・終了地点が特定され得ることを伝える。開始・終了地点の非表示などの保護方法は効果と地図上の残存情報を検証してから決める。完全な匿名化と表現しない。
4. 保存・共有はユーザーの操作で行う。アプリ内の作品削除と、写真や共有先に作られたコピーの削除は別であることを説明する。

保持する画像・座標・メタデータ、バックアップ、削除時の対象、権限取消後の既存作品の扱いは未決定。既存タイマーや保存データを変更しない設計とし、既存データとの互換性を実装時に確認する。
