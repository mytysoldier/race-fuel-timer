## Apple公式資料から分かること

- [WidgetKit: Displaying dynamic dates](https://developer.apple.com/documentation/widgetkit/displaying-dynamic-dates): OSが日時に基づく表示を更新できる。単一の日付を `.timer` で表示すると期限後は増加するので、残り時間には範囲付きカウントダウンを試す。
- [ActivityKit: Displaying live data](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities): データはアプリのActivityKit呼出し、またはサーバーからのActivityKit pushで更新する。日時表示が進むことだけでは次の予定データの切替を証明しない。
- `staleDate` は内容の更新期限。期限後の古い予定を現在の「次の予定」と断定しないため、`context.isStale` で警告表示する案を検証する。期限による内容更新やActivity終了を予約する機能としては扱わない。
- Live Activityは最長8時間アクティブ、終了後ロック画面には最長4時間追加で残り得る。アプリからの終了は `.immediate` を使う。長時間の実測は別途必要。

資料は2026-10-26に確認。上記は仕様確認であり実機の実測結果ではない。

## 検証アプリ

[spikes/LiveActivityProbe](../spikes/LiveActivityProbe/README.md) に独立したXcodeプロジェクトを置く。サーバー、Push、常時バックグラウンド処理は追加しない。1分×3回で短時間に複数予定を越える。通常間隔は10分×3回、継続時間制限は3時間×3回で実時間8時間超を確認する。

UIは、送信した予定番号・その予定時刻・最終送信時刻を残す。表示が古いままなのか、アプリが更新できたのかを区別する。ロック中はアプリ内のログだけで成功判定せず、ロック画面と通知の観測を記録する。
