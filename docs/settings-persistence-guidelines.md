# 設定永続化の設計・テスト指針

このドキュメントは、`UserDefaults` などへユーザー設定を保存する機能を追加・変更するときの設計とレビューのチェックリストである。保存対象とアダプタの責務は [技術アーキテクチャ](architecture.md) を正本とする。

## 先に決めること

設定項目ごとに、実装前に次を明確にする。

| 観点 | 決める内容 |
| --- | --- |
| 保存値 | 保存する項目、形式、バージョン、既定値 |
| 復元許容値 | 型、必須項目、数値範囲、文字数、組み合わせの制約 |
| 無効状態 | 機能を無効にしたときに関連する入力値を保持するか、消去するか |
| 破損時 | 保存設定なしへの復旧、壊れた保存値の削除、ユーザーへの案内 |

無効状態で関連値を保存しない仕様なら、画面の編集状態・保存モデル・復元処理のすべてで、その値を空に保つ。不正な値を「無効だから」と読み込み時だけ許容しない。

## 破損データの扱い

読み込み時は、次をすべて破損として扱い、保存設定なしへ復旧する。

- 保存値が期待する型ではない
- JSONの解析に失敗する
- 必須項目が欠損している
- 未対応のバージョンである
- 数値が有限値でない、または許容範囲外である
- 文字列が長すぎる、または項目間の制約を満たさない

フォールバックしたときは、同じ失敗を繰り返さないように保存値を削除する。保存アダプタは有効な保存モデルまたは保存設定なしを返し、未入力を許容する画面用の初期状態は呼び出し側で組み立てる。ユーザーが入力済みの設定を失ったと認識できるよう、画面上でも初期化を案内する。

## 実装・レビューの確認項目

- 保存・復元で表示用の数値を文字列化するときは、現在のロケールに対応する
- 保存形式を変更するときは、既存のバージョンとの互換性または安全な移行・初期化を確認する
- UIの無効化操作後に、保存されるモデルが仕様どおりの値になることを確認する
- 保存アダプタはSwiftUIの画面状態に依存させず、単体で破損値を検証できる形にする

## 最低限のテスト

- 正常な設定を保存して復元できる
- 保存値が存在しない初回起動では、保存設定なしを返し、復旧扱いにしない
- JSON破損、期待しない保存型、欠損、範囲外、未知バージョンでは保存設定なしへ復旧する
- 破損時に保存値を削除し、復旧状態を画面へ伝えられる
- 無効状態の関連フィールドが仕様どおりに保存・復元される
- ロケール依存の表示値を再編集する場合、表示・解析の往復が成立する
