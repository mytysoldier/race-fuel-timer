# Live Activity実装・QA（#69）

## 今回の仕様（2026-10-26ユーザー承認）

#75のSimulator結果に基づき、経過時間・実行状態と**更新時点の補給予定**を表示する。ロック中の複数予定の自動切替は保証しない。送信した予定時刻を過ぎたら、`staleDate` / `context.isStale` により古い予定の代わりに「最新の補給予定はアプリで確認」と案内する。アプリを前面に戻すと最新の予定に更新する。

#75は実機・長時間検証のためOPENを維持するが、今回のユーザー承認で#69着手のCLOSED待ちは外した。実機結果が出たものとは扱わない。サーバー、Push、常時バックグラウンド処理、ロック画面からの記録操作は追加しない。

## 実装

- 既存Sessionを読み取り専用のsnapshotへ変換する。`startedAt + totalPausedSeconds` を経過時間の起点にし、停止中は `pausedAt` で固定する。予定は `Session.nextReminder(at:)` を使い、到来済み・記録済みを除く。
- アプリとWidget extensionで共有する `RunActivityAttributes` を追加。ロック画面とDynamic Islandで表示する。
- 開始、停止／再開、記録、前面復帰で同期する。前面にいる間だけ次回予定の変化を確認し、内容が同じ場合はOSへの再送信をしない。背面へ移ると監視タスクを停止する。
- ActivityKitへの更新・終了を直列に処理し、終了中に古い更新が完了して表示が残る競合を避ける。
- 無効設定・開始失敗時もSessionと通知処理は継続し、アプリ内に案内する。OSの時間制限やユーザーの削除後に同じランの表示を勝手に作り直さない。
- 終了は `.immediate` で削除する。セッション非永続の仕様に合わせ、起動時は前回プロセスのActivityを削除する。完全終了直後の即時削除は保証しない。
- アプリ内で、予定は更新時点の内容であること、期限後はアプリを確認すること、ライブ更新は最長8時間でその後も表示が残り得ることを説明する。
